1. 실습 폴더 준비

Git으로 받은 실습 저장소 안의 week05를 그대로 사용합니다. ZIP으로 받았다면 week05 폴더 전체를 내려받아 압축을 풉니다. 모든 상황과 자료는 수업용 가상 자료입니다.

  • 따라하기 입력 자료: practice
  • 독립 미션 입력 자료: mission
  • 제출 기록: 검증 기록 틀

Kiro Crew에서 Task Runner를 열고 워크스페이스에 week05의 절대경로를 입력하세요. 입력은 practice/data, 출력 형식은 practice/출력형식.md, 결과는 submissions/practice/run01입니다. Agent에서 실행할 에이전트를 선택합니다.

내 컴퓨터에서 week05 경로 찾기

  • Windows: 탐색기에서 week05 폴더를 열고 주소 표시줄을 클릭해 전체 경로를 복사합니다. 해당 폴더에서 연 PowerShell은 pwd, 명령 프롬프트(CMD)는 cd로 현재 경로를 확인할 수 있습니다.
  • Mac: Finder에서 week05 폴더를 선택하고 ⌥⌘C로 경로를 복사합니다. 해당 폴더로 이동한 터미널에서 pwd로 확인할 수도 있습니다.
  • 터미널이 다른 위치라면 cd "week05의 전체 경로"로 이동한 뒤 경로를 확인합니다. Workspace에는 명령어·따옴표·PowerShell의 Path 제목을 빼고 경로만 붙여 넣으세요.

브랜치와 worktree: Git 저장소에서는 main을 바로 바꾸지 않도록 별도 작업 공간을 사용합니다. 브랜치는 변경 이력을 나누는 작업선이고, worktree는 그 브랜치의 파일을 펼친 별도 폴더입니다. 완료 후 결과를 확인하고 main에 통합하면 원래 폴더에 반영됩니다. Git이 없는 폴더는 실행 로그의 저장 위치에서 결과를 확인합니다.

practice/data의 창고 파일 3개를 직접 열어봅니다. 입력은 보존하고 결과는 submissions/practice/run01, submissions/practice/run02로 나눕니다.

2. 모호한 요청을 명세로 바꾸기

practice/업무요청.md를 열어 읽고 모호한 기준을 함께 살펴봅니다. 별도 초안 파일은 작성하지 않습니다. 강사의 안내에 따라 아래 제공 프롬프트를 입력하고, 다듬어진 명세를 검토하세요.

첫 업무 요청에서 ‘저재고’의 기준을 찾아보세요. 창고별 행의 수량과 전체 창고를 합친 품목 수량은 다릅니다. 이번 따라하기 1차에서는 창고별 행을 기준으로 정합니다.

출력 형식을 확인한 뒤 ‘작성’의 작업 설명에 아래 내용을 넣고 명세로 다듬기를 선택합니다.

다듬은 명세에서 입력 파일, 저재고 단위, 5 미만 조건, 저장 위치, 완료 조건을 읽습니다. 자신의 의도와 다르면 계획을 만들기 전에 수정하세요. ‘명세로 다듬기’는 입력문을 구조화하는 기능이며 원본 파일을 읽고 검증하는 단계는 아닙니다. 이번 실습에서는 정제된 명세로 계획을 만든 뒤 실제 실행을 시작합니다.

3. 실행 계획 확인과 실행

다듬어진 명세 아래의 명세로 플랜 만들기를 누릅니다. DAG에서 창고 A·B·C 집계가 세 갈래로 나뉘고, 세 결과가 통합 작업으로 모이는지 확인하세요. 공통 준비 작업이 앞에 있어도 됩니다. 세 창고가 한 줄로 연결됐다면 실행 전에 명세의 독립 작업 조건을 확인하고 계획을 다시 생성하세요.

워크스페이스가 week05인지 확인하고 ‘도구 호출 자동 승인’을 체크한 뒤 실행하세요. 이번 실행의 파일 작성과 명령 실행을 자동 승인하는 설정입니다.

승인 요청이 남아 있다면

상단 알림에서 요청한 대상과 명령을 확인하세요.

4. 결과와 원본 대조

먼저 원래 week05의 submissions/practice/run01을 열어 계산 코드, 창고별 중간 파일, result.json, report.md가 이번 실행 결과인지 확인하세요.

지정된 폴더에 결과 파일이 없다면

상단 우측 ‘채팅’에서 먼저 요청하세요.

이번 작업의 결과물 파일 위치와 브랜치를 확인해줘.

결과가 다른 브랜치에 있으면 다음과 같이 요청한 뒤 원래 제출 폴더를 다시 확인합니다.

이번 작업의 결과 브랜치를 main에 병합해줘.
  • 창고별·품목별 수량이 원본과 맞는지 확인합니다. 전체 합계는 54입니다.
  • 저재고 목록이 창고별 행 수량 5 미만 기준에 맞는지 확인합니다.
  • JSON과 보고서의 수치가 같은지 확인합니다.

확인한 내용은 검증 기록 틀을 참고해 짧게 적습니다. 검증 예제의 error-d.json은 총합이 같아도 품목별 값이 틀릴 수 있는 예시입니다.

제공 검사기는 2차 결과 전용입니다. 1차 결과는 위 기준으로 직접 대조하세요.

5. 기준 수정과 재실행

새 작업에서 같은 week05 작업 폴더를 지정합니다. 1차 결과를 보존하고, 이번에는 전체 창고의 품목별 총수량을 저재고 기준으로 사용합니다.

명세와 계획을 확인하고 ‘도구 호출 자동 승인’을 체크한 뒤 실행합니다. 먼저 submissions/practice/run02에서 결과를 확인하세요. 파일이 없으면 4번의 위치·브랜치 확인 절차를 따릅니다.

완료 후 확인

result.json과 report.md를 열어 수치가 같은지 확인하고, 1차와 2차의 저재고 목록이 어떻게 달라졌는지 짧게 기록하세요.

6. 독립 미션 · 공지 6건 브리핑

미션 안내와 공지 원문 N01–N06을 여세요. 워크스페이스는 week05, 저장 위치는 submissions/mission입니다. 판단 기준 시각은 2026-09-14 09:00, Asia/Seoul입니다.

기준을 정하고 실행

  1. 대상 독자, 포함·제외 기준, 정정 공지 처리 방법을 정합니다.
  2. 자신의 기준과 입력 경로·기준 시각·아래 세 제출 파일을 작업 설명에 적고 명세로 다듬기를 누릅니다. 확인한 명세를 submissions/mission/명세.md에 저장하도록 포함하세요.
  3. 명세로 플랜 만들기로 계획을 확인하고 도구 호출 자동 승인을 켜서 실행합니다.

결과 확인

먼저 원래 submissions/mission에서 결과를 엽니다. 없으면 4번의 위치·브랜치 확인 절차를 따릅니다.

  • N01–N06 각각의 포함·병합·제외 여부와 이유가 있는지 확인합니다.
  • 정정 공지의 최신 일정을 반영하고, 마감된 모집을 접수 중으로 안내하지 않습니다.
  • 원문에 없는 마감 시각 등은 ‘확인 필요’로 표시하고, 브리핑 항목마다 출처 공지 ID를 남깁니다.
  • 학생 본인이 원문과 직접 비교한 내용 한 가지 이상을 확인기록.md에 적습니다. 발견한 오류가 있으면 수정합니다.

실제 공지 발송 없이 브리핑 파일을 만듭니다.
