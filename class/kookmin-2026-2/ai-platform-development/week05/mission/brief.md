# 독립 미션 · 캠퍼스 공지 브리핑

공지 6건을 읽고, 자신이 정한 학생 독자에게 필요한 브리핑을 만드세요. Task Runner로 실행하고 아래 세 파일을 제출합니다.

## 1. 자료 열기

- Workspace: 실습 저장소의 `week05` 절대경로
- 입력: [data/notices.md](data/notices.md)의 N01–N06
- 판단 기준 시각: **2026-09-14 09:00, Asia/Seoul**
- 결과 폴더: `week05/submissions/mission/`

## 2. 기준을 정하고 실행하기

1. 대상 독자, 포함·제외 기준, 정정 공지 처리 방법을 정합니다. 예를 들어 ‘재학생 전체’와 ‘행사 참여를 원하는 학생’은 다른 독자입니다.
2. 자신이 정한 기준과 입력 경로·기준 시각·세 제출 파일을 작업 설명에 적고 **명세로 다듬기**를 누릅니다. 다듬어진 명세가 자신의 기준과 맞는지 확인합니다.
3. 확인한 명세를 `submissions/mission/명세.md`에 저장하도록 작업에 포함합니다. 아래 양식의 항목을 참고하세요. 별도 초안 파일은 필요 없습니다.
4. **명세로 플랜 만들기**를 누르고 계획을 확인한 뒤 **도구 호출 자동 승인**을 켜고 실행합니다.

## 3. 결과 확인하기

먼저 원래 `week05/submissions/mission/`에서 결과를 엽니다. 파일이 없다면 우측 상단 **채팅**에서 ‘이번 작업의 결과물 파일 위치와 브랜치를 확인해줘’라고 요청하세요. 다른 브랜치에 있으면 ‘이번 작업의 결과 브랜치를 main에 병합해줘’라고 요청한 뒤 폴더를 다시 확인합니다.

- N01–N06 각각의 포함·병합·제외 여부와 이유가 있는지 확인합니다. 병합했다면 함께 처리한 공지 ID를 적습니다.
- 정정 공지는 최신 일정을 반영하고, 마감된 모집을 접수 중으로 안내하지 않습니다.
- 원문에 없는 날짜·마감 시각·링크를 추측하지 않습니다. 필요한 정보가 없으면 ‘확인 필요’로 표시합니다.
- 브리핑 각 항목에 출처 공지 ID를 적습니다. 병합 항목은 관련 ID를 모두 적습니다.
- 학생 본인이 브리핑 내용 한 가지 이상을 원문과 직접 비교해 `확인기록.md`에 적습니다. 발견한 오류가 있으면 수정합니다.

## 4. 제출 파일

| 파일 | 필수 내용 | 참고 양식 |
|---|---|---|
| `명세.md` | 대상 독자, 기준 시각, 포함·제외 기준, 정정 처리 방법 | [명세 양식](templates/명세.md) |
| `브리핑.md` | 선별한 공지의 제목, 핵심 안내, 관련 일정, 출처 ID | [브리핑 양식](templates/브리핑.md) |
| `확인기록.md` | N01–N06 처리 결과·이유, 직접 원문과 비교한 내용 1건 이상 | [확인기록 양식](templates/확인기록.md) |

세 파일은 `week05/submissions/mission/`에 저장합니다. 양식은 형식 참고용이며 제출 전에 빈 항목을 채웁니다. 최종 브리핑 항목 수는 자신의 포함·병합·제외 기준에 따라 달라집니다.

자동 검사 코드, 일부러 만든 오류, 종료코드와 재검사 기록은 필수 제출물이 아닙니다. 실제 공지 발송 없이 브리핑 파일을 만들어 GitHub 과제로 제출합니다.
