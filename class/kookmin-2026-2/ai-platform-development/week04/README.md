빛담 동아리의 가을사진전(E04)을 준비합니다. 학교와 동아리의 문서에서 적용 조건을 찾고, 참가 신청과 회계를 계산해 근거가 있는 운영 판단을 남깁니다.

**전체 수업 안내:** [시작하기.html](시작하기.html)을 내려받은 폴더에서 브라우저로 엽니다. 스킬 복습부터 RAG, 계산·보고서, 제출과 핵심 정리까지 순서대로 따라갈 수 있습니다.

지난주 사용한 본인의 복제 저장소에서 개인 변경 사항을 먼저 확인·커밋한 뒤 업스트림 자료를 받습니다. 3주차에 설정한 Merge 방식이 유지되므로 같은 저장소에서는 설정을 반복하지 않습니다.

## 파일 역할

| 위치 | 내용 | 사용 시점 |
|---|---|---|
| [documents/](documents/) | 학교 지침·동아리 규칙·승인서·회의 메모·회계 기준 8개 | 처음에 지식 소스로 등록 |
| [data/참가신청.csv](data/참가신청.csv) | E04 참가 신청 200건 | 전체 파일을 Python으로 계산 |

| [data/구매계획.csv](data/구매계획.csv) | 앞으로 구매할 물품 12개 항목 | 이미 처리한 회계와 구분해 계산 |

| [submissions/](submissions/) | 각자 만든 결과를 저장할 폴더 | 실습 중 저장하고 자기 포크에 제출 |

## 진행 순서

1. 강사 예시를 보고 data-to-html 스킬을 만들어 documents·data 요약 HTML을 확인합니다.
2. 청킹·임베딩, 모델 역할, 벡터 검색, RAG와 파인튜닝을 구분합니다.
3. documents의 기본 문서 8개를 지식에 등록하고 검색·원문 확인 후 관련 근거를 대화에 연결합니다.
4. data의 CSV 3개를 Python으로 전체 계산하고 data-to-html로 초기 운영 보고서 HTML을 만듭니다.
5. 집계 Python을 club-budget-check 스킬로 만들고, updates 원본을 유지한 채 변경 승인서의 복사본을 documents에 넣어 인덱싱을 확인합니다.
6. 세 질문을 재검색하고 답변·근거·확인 기록과 최종 HTML을 submissions에 저장합니다. 최종 HTML은 수업 Slack에 제출하고 결과 폴더는 내 GitHub에 커밋·푸시합니다.
7. 핵심을 정리한 뒤 [다음 주 과제](mission/시작하기.html)를 진행합니다. 과제 결과는 mission/submissions에 저장하고 다음 주까지 최종 HTML을 수업 Slack에 제출합니다.

`week04` 전체를 처음부터 지식 소스로 등록하면 후반에 사용할 변경 승인서까지 함께 들어갈 수 있습니다. 변경 전후를 비교할 수 있도록 처음에는 `updates/`를 등록하지 않습니다.

초기 질문: 빛담 가을사진전(E04)의 승인된 참가 정원은 몇 명인가요? 출처와 조항을 함께 보여주세요.

## 저장과 제출

submissions에는 각자 실습하면서 실제로 만든 결과물을 남깁니다. 앞에서 만든 초기 운영 보고서는 HTML입니다. 요약 HTML, 집계 결과, 실행 코드, 변경 후 보고서 등은 예시이며 모든 항목이나 파일 이름·개수·크기를 맞출 필요는 없습니다.

원본 CSV는 보존합니다. 저장한 파일을 직접 열어 확인한 뒤 이번 실습 결과만 커밋하고 본인의 `origin` 포크에 Push합니다. GitHub에서도 실제 파일과 내용을 확인합니다. 최종 HTML은 브라우저에서 확인한 뒤 수업 Slack에 파일로 첨부합니다.
