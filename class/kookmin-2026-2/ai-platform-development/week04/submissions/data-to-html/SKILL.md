# data-to-html

여러 개의 `.md`/`.txt` 문서를 문서별로 요약하고, 여러 `.csv`를 핵심 표로 집계해 **하나의 HTML 파일**로 출력한다. 특정 폴더·파일에 묶이지 않고, 넘긴 경로(폴더 또는 파일)를 확장자로 나눠 처리한다. 요약·집계는 코드로 하고(파이썬 표준 라이브러리만), 값이나 문구 판단은 사람이 결과 HTML을 열어 확인한다.

## 입력
- 위치 인자 `inputs`: 하나 이상의 **폴더 또는 파일 경로**.
  - 폴더는 하위까지 훑어 `.md`/`.txt`는 요약 대상, `.csv`는 표 집계 대상으로 자동 분류.
  - 파일을 직접 넘겨도 됨.
- `--out <file.html>`: 출력 HTML 경로 (필수)
- `--title <문자열>`: HTML 제목 (선택, 기본 "문서·데이터 요약")

CSV는 알려진 스키마면 전용 집계, 아니면 일반 미리보기(상위 N행 + 행수)로 표시한다.

## 원칙
- 파이썬 3.10+ **표준 라이브러리만** 사용(`csv`, `argparse`, `pathlib`, `html`, `re`). 외부 패키지·네트워크 없음.
- CSV는 `utf-8-sig`로 읽어 BOM 대응. 금액은 정수 원 단위로 취급.
- **원본 파일은 수정하지 않는다.** 출력은 `--out`에만 쓴다.
- 문서 요약 = 첫 헤딩(제목) + 문서 ID/날짜/행사 ID 등 메타 + **핵심 사실(일시·장소·정원·한도·금액 등 `키: 값`)** + 각 조/문단 **본문 전체**. 원문을 지어내지 않고 있는 그대로 발췌한다. 숫자·금액·정원·날짜는 `<mark>`로 강조한다.
- HTML은 외부 CSS/JS 없이 인라인 스타일로 자기완결형. 브라우저로 바로 열 수 있게 한다. (Pretendard 폰트만 CDN에서 로드)

## 텍스트 요약에 담는 것
- **핵심 사실 칩(`.facts`)**: 본문의 `키: 값` 줄 중 일시·일자·장소·정원·인원·한도·금액·단가·마감·기준·대상 등 중요한 항목만 골라 카드 상단에 칩으로 강조.
- **조항 본문**: 헤딩(조)별로 첫 문장만 자르지 않고 문단 전체를 이어 담는다.
- **숫자 강조**: 금액(4,000원)·정원(180명)·날짜(2026-09-28)·시각(14:00) 등을 `<mark>`로 시각 강조.

## CSV 핵심의 시각적 강조
각 CSV 집계 위에 **KPI 카드(`.stats`)**로 헤드라인 수치를 크게 보여준 뒤 표를 잇는다.
- 참가신청: 총 신청 · 확정 인원 · 신청상태 종류
- 회계내역: 거래 건수 · 수입 계열 합 · 지출 계열 합 · 전체 순액
- 구매계획: 예정 항목 수 · '고정' 소계

## 디자인 규칙 (HTML 출력)
- **shadcn/ui식 컴포넌트 구조**: HSL 토큰(`--background/--card/--border/--muted/--primary`)과 `--radius`로 카드·배지·테이블을 단정하게. 라이트/다크 자동(`prefers-color-scheme`).
- **Apple식 미니멀리즘**: 넉넉한 여백, 절제된 타이포(음수 letter-spacing, tabular-nums), 저채도 뉴트럴 팔레트. 과한 색·장식 금지.
- **Flowbite식 앱 패턴**: 상단 스티키 앱바로 제목·위계를 고정, 콘텐츠는 중앙 정렬 컨테이너. 섹션 헤더로 정보 위계를 명확히.
- **간격 = Tailwind 8px 스케일**: 8/16/24/32/48px만 사용.
- **폰트**: 한글 기본 Pretendard(CDN), 폴백 system-ui.
- **Magic UI는 절제**: 앱바 backdrop-blur, 옅은 구분선 glow, 카드 스크롤 진입 reveal 정도만. `prefers-reduced-motion` 존중.

## 알려진 CSV 스키마와 집계
- **참가신청** (`행사_ID,이름,신청상태,…,인화체험,식음료` 류): 신청상태별 인원, 신청상태='확정' 기준 옵션(인화체험·식음료)별 '신청' 수. `신청/미신청/받지않음/빈칸`을 구분한다.
- **회계내역** (`거래일,행사_ID,재원,유형,항목,금액,…`): 행사×재원별, 그리고 유형(수입/지출/환불입금/환불지급)별 합계와 건수. 부호는 수입·환불입금 +, 지출·환불지급 −.
- **구매계획** (`물품,수량기준,계수,단가,예정재원,용도`): 항목별 예정비용(수량기준 '고정'=계수, '참가자'=계수×확정인원). 확정인원을 모르면 계수만 표시하고 참가자 곱은 비워 둔다. **이미 처리된 회계와 합산하지 않는다.**

스키마 자동 판별은 헤더의 특징 컬럼으로 한다. 새 CSV가 오면 일반 미리보기로 떨어진다.

## 사용법 (PowerShell)
```powershell
cd C:\Users\1153g\.kiro\crew\skills\data-to-html
python .\scripts\build_report.py `
  "<week04>\documents" "<week04>\data" `
  --out "<week04>\submissions\운영보고서.html"
echo "EXIT=$LASTEXITCODE"
```
폴더를 여러 개, 혹은 개별 파일을 섞어 넘길 수 있다. week04 관련 모든 산출물(생성 HTML·스킬 사본)은 `submissions/` 폴더에 저장한다.

## 종료 코드
- `0` 성공(HTML 생성)
- `1` 입력 오류(폴더/파일 없음, 인자 누락)
- `2` 처리 오류(CSV 파싱 실패 등)

## 확인
결과 HTML을 브라우저로 직접 열어 문서 요약과 표 값을 원본과 대조한다. 참가신청 확정 인원은 구매계획의 '참가자' 곱에 재사용할 수 있다.
