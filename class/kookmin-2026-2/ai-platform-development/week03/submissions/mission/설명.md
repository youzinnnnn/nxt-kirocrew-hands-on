# 설명

## 1. 개요

### 에이전트

* **역할:** 동아리 행사 준비 담당
* **워크스페이스:** `week03`

### 스킬

* **Name:** `event-roster-check`
* **Description:** 행사 안내와 참가신청 CSV를 읽고, 참가 인원과 간식 수량을 코드로 집계한 뒤 준비할 일을 정리한다.
* **Triggers:** 행사 준비, 참가신청, 신청 현황, 인원 집계, 간식 수량

### 목적

동아리 행사 참가신청 CSV가 변경될 때마다 참가 인원과 간식 수량을 반복해서 확인하기 위한 스킬이다.

핵심 원칙은 **"수량 집계는 코드가, 판단과 정리는 AI가"**이다.

| 역할      | 담당                                                               |
| ------- | ---------------------------------------------------------------- |
| 수량 집계   | `scripts/count_roster.py`가 CSV를 읽어 참가 인원, 간식 수량, 생수 수량, 미응답자를 계산 |
| 판단 및 정리 | AI가 집계 결과를 `행사안내.md`의 규칙과 비교하여 준비할 일, 확인할 사람, 현재 상태를 보고서로 정리     |

---

## 2. 입력 자료

| 자료         | 내용                                  |
| ---------- | ----------------------------------- |
| `행사안내.md`  | 일정, 정원, 인원 집계 규칙, 간식 주문 규칙, 마감, 준비물 |
| `참가신청.csv` | 참가 신청 현황                            |

### CSV 형식

헤더는 다음과 같아야 한다.

```text
신청번호,이름,학년,참가 여부,간식 선택
```

* 신청번호 1개는 1명을 의미한다.
* 명단이 변경되면 해당 행만 수정한다.

---

## 3. 집계 규칙

모든 수량은 `scripts/count_roster.py`가 계산한다.

### 3.1 참가 인원

* `참가 여부`가 `참가`인 사람만 참가 인원에 포함한다.
* `불참`은 참가 인원에서 제외한다.

### 3.2 간식

간식은 **참가자에 대해서만** 집계한다.

| 간식 선택   | 처리 방법    |
| ------- | -------- |
| `샌드위치`  | 1인 1개    |
| `주먹밥`   | 1인 1개    |
| `받지 않음` | 주문하지 않음  |
| 빈칸      | 미응답으로 처리 |

> `받지 않음`과 빈칸은 서로 다른 값이므로 절대 합치지 않는다.

빈칸인 참가자는 임의로 메뉴를 지정하지 않고 **확인할 사람**으로 분류한다.

### 3.3 불참자

* 불참자는 인원 집계에서 제외한다.
* 불참자의 간식 선택도 집계하지 않는다.
* 불참자의 빈칸은 미응답 목록에 포함하지 않는다.

### 3.4 생수

생수는 간식 선택과 관계없이 **참가 인원수만큼** 준비한다.

```text
생수 수량 = 참가 인원수
```

### 3.5 정원

참가 인원이 정원을 초과하면 `정원초과`를 `true`로 설정한다.

```text
참가 인원 > 정원 → 정원초과: true
참가 인원 ≤ 정원 → 정원초과: false
```

### 3.6 입력 오류

다음과 같은 경우 집계를 수행하지 않고 오류 이유를 알린다.

* CSV 헤더가 올바르지 않은 경우
* `참가 여부`에 `참가` 또는 `불참` 외의 값이 있는 경우

## 4. 집계 결과 JSON

`count_roster.py`는 항상 동일한 구조의 JSON을 출력한다.

| 항목      | 자료형 | 설명                     |
| ------- | --- | ---------------------- |
| `참가_인원` | 정수  | 참가자로 집계된 사람 수          |
| `불참_인원` | 정수  | 불참으로 제외된 사람 수          |
| `간식`    | 객체  | 메뉴별 수량                 |
| `생수`    | 정수  | 참가 인원수와 동일             |
| `미응답`   | 목록  | 참가자 중 간식 선택이 빈칸인 사람    |
| `정원`    | 정수  | `행사안내.md`에 정의된 정원      |
| `정원초과`  | 불리언 | 참가 인원이 정원을 초과하면 `true` |

`간식` 객체의 구조는 다음과 같다.

```json
{
  "샌드위치": 0,
  "주먹밥": 0,
  "받지_않음": 0
}
```

`미응답`은 다음과 같은 구조로 출력한다.

```json
[
  {
    "신청번호": "A07",
    "이름": "홍길동"
  }
]
```

## 5. 실행 절차

### 5.1 Python 버전 확인

이 컴퓨터에서 Python 3을 실행할 수 있어야 한다.

```powershell
python --version
```

### 5.2 행사 안내 확인

AI가 먼저 `행사안내.md`를 읽고 다음 정보를 정리한다.

* 행사 일정
* 정원
* 신청 마감
* 인원 집계 규칙
* 간식 주문 규칙
* 준비물


### 5.3 종료 코드 확인

| 종료 코드 | 의미           | 처리                       |
| ----- | ------------ | ------------------------ |
| `0`   | 집계 성공        | 다음 단계 진행                 |
| `1`   | 집계 실패        | 오류 내용을 확인하고 CSV 수정 후 재실행 |
| `2`   | 입력 파일을 읽지 못함 | 파일 경로 확인 후 재실행           |

`1` 또는 `2`가 발생한 경우 집계 결과를 저장하지 않는다.

### 5.4 보고서 작성

집계 JSON을 바탕으로 AI가 `행사안내.md`의 규칙과 비교하여 보고서를 작성한다.

보고서에는 다음 내용을 포함한다.

* 참가 인원 및 정원 초과 여부
* 메뉴별 간식 수량
* 생수 수량
* 미응답자 명단
* 미응답이 있는 경우 간식 수량을 **확정 전**으로 표시
* 미응답자 확인 마감
* 당일 준비물 체크리스트
* 현재 상태

> **주의:** `수량 확정`과 `실제 주문 완료`는 서로 다른 상태로 구분한다.

### 5.6 결과 저장

최종 결과는 다음 경로에 저장한다.

```text
submissions/mission/
```

저장 대상:

```text
집계 결과 JSON
보고서 MD
```

## 6. 반복 사용

참가 명단이 변경되면 동일한 집계 절차를 다시 실행한다.

예:

```text
불참 → 참가
참가 → 불참
간식 선택 변경
신규 참가자 추가
```

명단이 변경될 때마다 사람이 직접 숫자를 다시 세지 않는다.

```text
CSV 수정
   ↓
count_roster.py 재실행
   ↓
변경된 수량 확인
   ↓
AI가 보고서 갱신
```

## 7. 변경 후 검증 기준

스킬 또는 CSV 변경 후 다음 항목을 확인한다.

* [ ] 불참자를 참가 인원에서 제외했는가?
* [ ] 불참자를 간식 수량에서 제외했는가?
* [ ] 불참자를 생수 수량에서 제외했는가?
* [ ] 불참자의 빈칸을 미응답으로 처리하지 않았는가?
* [ ] `받지 않음`과 빈칸을 구분했는가?
* [ ] 참가자 1명이 `불참 → 참가(샌드위치)`로 변경되면 참가 인원, 샌드위치, 생수가 각각 1씩 증가하는가?
* [ ] 그 외 수량은 변경되지 않는가?
* [ ] 미응답을 임의로 메뉴로 채우지 않는가?
* [ ] 참가 인원이 정원을 초과하면 `정원초과`가 `true`가 되는가?
* [ ] 오류 발생 시 집계 결과가 저장되지 않는가?

---

## 8. 기준 검증 결과

* [x] 불참자를 인원·간식·생수에서 모두 제외
  → A10 제외됨.

* [x] `받지 않음`과 빈칸을 구분
  → A04(`받지 않음`)와 A07(빈칸)을 분리 처리.

* [x] 참가자 한 명이 `불참 → 참가(샌드위치)`로 변경될 경우 참가 인원·샌드위치·생수가 각각 1 증가
  → 모두 `+1` 확인.

* [x] 그 외 수량은 그대로 유지하고 미응답을 임의로 채우지 않음
  → 주먹밥·받지 않음·미응답 수량 불변.

---

## 9. 핵심 원칙 요약

> **집계는 코드, 판단은 AI.**

* 참가 인원·간식·생수·미응답 → `count_roster.py`가 집계
* 일정·정원·주문 규칙·준물 → `행사안내.md`를 기준으로 판단
* 집계 결과 → 고정된 JSON 구조로 출력
* 종료 코드 → 성공 및 오비류 상태 판단
* 결과 JSON 및 보고서 → `submissions/mission/`에 저장
* 명단 변경 → 동일한 코드로 재실행
* `받지 않음`과 빈칸 → 반드시 구분
* 수량 확정과 실제 주문 완료 → 별도 상태로 관리
